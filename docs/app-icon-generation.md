# App Icon Generation

This document is the durable playbook for generating, evaluating, and shipping Local
Brain app icons. It captures the current repository pipeline, the lessons learned
from prior icon iterations, and the prompt discipline needed when using AI-generated
source artwork.

The short version:

1. Generate or choose **full-bleed square source art**.
2. Save it as `apps/desktop/assets/app-icon-source.png`.
3. Run `pnpm --filter @local-brain/desktop icons`.
4. Verify the source, processed master, and generated platform icons.
5. Commit the source, processed master, and generated icon outputs together.

Do not ask an image model to generate a finished rounded macOS icon. In this repo,
the source artwork and the platform icon treatment are separate steps.

## Why This Exists

App icons look deceptively simple. The first Local Brain icon iterations exposed a
few traps:

- Tauri's icon command is a platform format generator, not a native macOS icon
  designer.
- Feeding Tauri a full square bitmap can produce an icon that looks too large next
  to real macOS Dock icons.
- Baking a rounded square, black border, shadow, or "app icon tile" into the source
  image makes the downstream icon renderer double-process the artwork.
- macOS icons need visual margin, material treatment, and a full `.icns` ladder.
- PNG bit depth matters. Earlier icon assets were 16-bit RGBA and triggered a Tauri
  runtime icon panic. Use 8-bit PNGs.
- Generated image previews are useful for sign-off, but the selected artifact must
  be copied into the repo before it can become durable.

The current pipeline solves these by separating **source art** from **platform
rendering**:

- Tauri generates the normal cross-platform icon set from one source PNG.
- On macOS, the script then replaces `icon.icns` with an Apple-rendered and padded
  version using Xcode's Icon Composer renderer (`ictool`), `sips`, and `iconutil`.

## Current Repo Files

The active icon pipeline is owned by the desktop app:

```text
apps/desktop/
+-- assets/
|   +-- app-icon-source.png       # canonical full-bleed source artwork
|   +-- app-icon-processed.png    # generated 1024px macOS preview/master
|   +-- icon-concepts/            # optional concept explorations, not consumed
+-- scripts/
|   +-- generate-icons.mjs        # deterministic icon generation pipeline
+-- src-tauri/
    +-- icons/                    # generated platform outputs consumed by Tauri
```

The package script is:

```json
{
  "scripts": {
    "icons": "node scripts/generate-icons.mjs"
  }
}
```

Run it from the repository root:

```bash
pnpm --filter @local-brain/desktop icons
```

## Terminology

Use these terms precisely:

- **Source artwork:** `apps/desktop/assets/app-icon-source.png`. This is the
  full-bleed image created by a designer or image model. It should not contain a
  rounded app tile or outer border.
- **Processed macOS master:** `apps/desktop/assets/app-icon-processed.png`. This is
  generated by the script from the Apple-rendered 1024px rendition after padding.
- **Tauri icon set:** the generated files under `apps/desktop/src-tauri/icons`.
  These include PNG, ICO, ICNS, AppX, iOS, and Android outputs.
- **Icon Composer package:** a temporary `.icon` folder generated by the script so
  `ictool` can render the source through Apple's material pipeline.
- **Iconset:** a temporary `.iconset` folder containing `icon_16x16.png`,
  `icon_16x16@2x.png`, and so on. `iconutil` converts this folder into `icon.icns`.

## Desired Source Artwork

The source artwork should look like a strong square illustration, not a finished
application icon.

For Local Brain, a good source image usually has:

- `1254x1254` or larger square dimensions.
- 8-bit RGB or RGBA PNG.
- Full-bleed color to all four edges.
- No text, letters, watermarks, or numerals.
- No transparent padding.
- No black border.
- No baked rounded square, squircle, bevel, or Dock tile.
- No drop shadow outside the artwork.
- A central symbol that remains readable when scaled down.
- A central mark using roughly 50-60% of the canvas unless the shape is extremely
  compact.
- A clear **internal subject safe zone**: important nodes, lobes, rings, glows, and
  connecting edges should stay comfortably inside the central 65-70% of the square.
- Enough calm background/negative space that Apple's renderer can add margin without
  crushing the main idea.

This distinction matters: the **background** should be full-bleed, but the **main
glyph** should not be near the edges. Apple's Icon Composer rendering, safe-zone
padding, rounded icon shape, and small-size scaling can visually crop or crowd
important subject matter if the source art places the mark too far left, right, top,
or bottom. For bilateral icons, such as the twin-cluster graph, the two halves should
be treated as one combined centered symbol with visible breathing room on every side.

For the current Local Brain direction, the strongest prompt theme has been:

- Purple, indigo, and electric amethyst color system.
- Glossy but restrained glass material.
- A bilateral "twin cluster" graph.
- A small number of luminous nodes.
- One clear cyan bridge between clusters.
- Magenta and cyan highlights.
- Abstract memory/network semantics without becoming a literal brain.

## What Not To Generate

Do not generate:

- A rounded-square macOS icon tile.
- A black-framed square.
- A transparent cutout icon.
- A literal anatomical brain.
- A skull, robot face, document, page, lock, or generic AI sparkle mark.
- A dense graph mesh with too many small edges.
- A final `.icns` visual inside a PNG.

The icon script creates the rounded and padded macOS result later. If the source image
already has those treatments, the final icon will look heavy, double-framed, or too
small.

```text
Style/medium: Premium macOS-quality product icon source art, glossy glass, rich
```


## Current Generation Pipeline

The script is `apps/desktop/scripts/generate-icons.mjs`.

At a high level:

```text
app-icon-source.png
        |
        | 1. pnpm tauri icon <source>
        v
src-tauri/icons/*              # cross-platform generated set
        |
        | 2. macOS only:
        |    create temp LocalBrain.icon package
        |    copy source into LocalBrain.icon/Assets/
        |    write icon.json
        |    render with ictool at smaller safe-zone sizes
        |    pad rendered images with sips
        |    assemble iconset
        |    convert iconset to icon.icns with iconutil
        v
src-tauri/icons/icon.icns      # Apple-rendered/padded macOS icon
assets/app-icon-processed.png  # generated 1024px preview/master
```

### Phase 1: Tauri Generates Platform Icons

The script first runs:

```bash
pnpm tauri icon apps/desktop/assets/app-icon-source.png
```

Tauri writes the platform icon set under `apps/desktop/src-tauri/icons`.

Tauri's docs describe `tauri icon` as taking an input file and creating the icons
needed for the various platforms. The important mapping is:

- `icon.icns` for macOS.
- `icon.ico` for Windows.
- `*.png` for Linux.
- `Square*Logo.png` and `StoreLogo.png` for AppX/MS Store targets.

The script intentionally lets Tauri produce the broad platform set first because this
keeps Windows, Linux, iOS, Android, and AppX outputs aligned with Tauri defaults.

### Phase 2: macOS Icon Composer Rendering

On macOS, the script then replaces only:

```text
apps/desktop/src-tauri/icons/icon.icns
```

This is necessary because Tauri's default resized `.icns` can look oversized in the
Dock. The macOS-specific phase uses:

```text
/Applications/Xcode.app/Contents/Applications/Icon Composer.app/Contents/Executables/ictool
/usr/bin/sips
/usr/bin/iconutil
```

`ictool` renders the source image through Apple's Icon Composer material system.
`sips` pads the rendered image to the final icon size. `iconutil` packages the
iconset into a real `.icns`.

### Temporary `.icon` Package

The script creates a temporary package like:

```text
LocalBrain.icon/
+-- Assets/
|   +-- app-icon-source.png
+-- icon.json
```

The generated `icon.json` currently looks like this:

```json
{
  "fill": {
    "automatic-gradient": "extended-srgb:0.00000,0.53333,1.00000,0.45"
  },
  "groups": [
    {
      "layers": [
        {
          "image-name": "app-icon-source.png",
          "name": "Local Brain"
        }
      ],
      "shadow": {
        "kind": "neutral",
        "opacity": 0.35
      },
      "translucency": {
        "enabled": true,
        "value": 0.3
      }
    }
  ],
  "supported-platforms": {
    "circles": ["watchOS"],
    "squares": "shared"
  }
}
```

This is not a hand-authored design asset. It is a minimal generated document that
lets Apple's renderer apply material, rim, shadow, and translucency to the source
image.

The fill alpha, shadow opacity, and translucency value are intentionally kept below
their default full-strength values. They soften Apple's generated material treatment,
but they do not fully control every visible rim highlight. If the source artwork has
a bright full-bleed arc near the edge, that arc can still read as a harsh border after
Icon Composer rounds and lights the icon.

### macOS Safe-Zone Sizes

The most important detail is that the script does **not** render a 1024px macOS image
directly at 1024px. It renders smaller, then pads to the final size.

Current table:

| Final size | Render size | Iconset filenames |
| ---: | ---: | --- |
| 16 | 14 | `icon_16x16.png` |
| 32 | 26 | `icon_16x16@2x.png`, `icon_32x32.png` |
| 64 | 52 | `icon_32x32@2x.png` |
| 128 | 104 | `icon_128x128.png` |
| 256 | 206 | `icon_128x128@2x.png`, `icon_256x256.png` |
| 512 | 412 | `icon_256x256@2x.png`, `icon_512x512.png` |
| 1024 | 824 | `icon_512x512@2x.png` |

This is approximately an 80.5% render size:

```text
824 / 1024 = 0.8046875
```

That margin is what keeps the macOS icon from looking too large next to system and
third-party Dock icons.

## Why Not Just Use Tauri?

Tauri's icon command is still valuable, but it is not sufficient for native macOS
visual polish.

The distinction:

- Tauri solves file generation and platform placement.
- Apple solves macOS icon rendering, material, margin, and shape expectations.

Using only Tauri created a valid icon set, but visually the Dock icon looked like a
literal square bitmap resized into the slot. It lacked the Apple-style inset and rim
and appeared too large relative to neighboring apps.

Using a single pre-padded source for all platforms is also a bad tradeoff. It can make
the macOS icon look better while making Windows, Linux, tray, or mobile icons look too
small. This repo therefore keeps the source image full-bleed, lets Tauri generate the
cross-platform set, and replaces only macOS `icon.icns`.

## Why Not Hand-Roll the macOS Look With ImageMagick?

We tried a deterministic ImageMagick-style approach first:

- rounded mask
- blurred/dimmed background
- central image safe zone
- rim highlights
- inner shadows

That was the wrong layer of abstraction. It made the script fragile, and small
composition mistakes produced artifacts such as incorrect alpha, too much padding, or
suppressed artwork detail.

The better deterministic path is to let Apple's renderer do the Apple-specific
material rendering and use our script only to assemble the package, apply margin, and
write the expected files.

## Step-By-Step: Creating A New Icon

### 1. Generate Or Choose Source Art

Generate several source-art candidates with the AI prompt rules above. Save candidates
under:

```text
apps/desktop/assets/icon-concepts/
```

Recommended naming:

```text
local-brain-icon-v4-01-short-description.png
local-brain-icon-v4-02-short-description.png
local-brain-icon-v4-contact-sheet.png
```

Concept files are useful for design review, but they are not consumed by the app.

### 2. Make A Contact Sheet

For five candidates:

```bash
magick \
  apps/desktop/assets/icon-concepts/local-brain-icon-v4-01.png \
  apps/desktop/assets/icon-concepts/local-brain-icon-v4-02.png \
  apps/desktop/assets/icon-concepts/local-brain-icon-v4-03.png \
  apps/desktop/assets/icon-concepts/local-brain-icon-v4-04.png \
  apps/desktop/assets/icon-concepts/local-brain-icon-v4-05.png \
  -thumbnail 260x260 \
  -background '#111018' \
  -gravity center \
  -extent 300x300 \
  +append \
  apps/desktop/assets/icon-concepts/local-brain-icon-v4-contact-sheet.png
```

Review the contact sheet for:

- silhouette
- small-size readability
- accidental borders
- accidental text
- whether the icon still reads when squinting
- whether the central mark is too large
- whether the central mark is too busy

### 3. Promote The Selected Candidate

Copy the selected candidate to the canonical source path:

```bash
cp apps/desktop/assets/icon-concepts/local-brain-icon-v4-01-short-description.png \
  apps/desktop/assets/app-icon-source.png
```

Do not delete the concept file unless you are intentionally cleaning up design
exploration artifacts.

### 4. Regenerate Icons

Run:

```bash
pnpm --filter @local-brain/desktop icons
```

Expected effects:

- `apps/desktop/assets/app-icon-source.png` remains the source.
- `apps/desktop/assets/app-icon-processed.png` is regenerated.
- `apps/desktop/src-tauri/icons/*` is regenerated.
- On macOS with Xcode/Icon Composer installed, `icon.icns` is replaced by the
  Apple-rendered/padded version.
- On non-macOS, only the Tauri generation phase runs.

### 5. Verify File Metadata

Run:

```bash
file \
  apps/desktop/assets/app-icon-source.png \
  apps/desktop/assets/app-icon-processed.png \
  apps/desktop/src-tauri/icons/icon.png \
  apps/desktop/src-tauri/icons/icon.icns \
  apps/desktop/src-tauri/icons/icon.ico
```

Expected:

```text
app-icon-source.png:    PNG image data, 1254 x 1254, 8-bit/color RGB, non-interlaced
app-icon-processed.png: PNG image data, 1024 x 1024, 8-bit/color RGBA, non-interlaced
icon.png:               PNG image data, 512 x 512, 8-bit/color RGBA, non-interlaced
icon.icns:              Mac OS X icon, ... "ic12" type
icon.ico:               MS Windows icon resource ...
```

The source dimensions can vary if a future selected source is different, but it must
be square and should be 8-bit.

Also useful:

```bash
sips -g pixelWidth -g pixelHeight -g hasAlpha \
  apps/desktop/assets/app-icon-source.png \
  apps/desktop/assets/app-icon-processed.png \
  apps/desktop/src-tauri/icons/icon.png
```

Expected:

- Source: square, no alpha is fine.
- Processed: `1024x1024`, alpha yes.
- Tauri `icon.png`: `512x512`, alpha yes.

### 6. Verify The `.icns` Ladder

Unpack the generated `.icns`:

```bash
rm -rf /tmp/local-brain-icon.iconset
iconutil -c iconset \
  -o /tmp/local-brain-icon.iconset \
  apps/desktop/src-tauri/icons/icon.icns

find /tmp/local-brain-icon.iconset -maxdepth 1 -type f -print | sort | xargs file
```

Expected files:

```text
icon_16x16.png
icon_16x16@2x.png
icon_32x32.png
icon_32x32@2x.png
icon_128x128.png
icon_128x128@2x.png
icon_256x256.png
icon_256x256@2x.png
icon_512x512.png
icon_512x512@2x.png
```

The `icon_512x512@2x.png` file should be `1024x1024`.

### 7. Create A Preview Sheet

This is helpful for reviewing the source and generated treatment side by side:

```bash
magick apps/desktop/assets/app-icon-source.png \
  -resize 300x300 \
  -background '#111018' \
  -gravity center \
  -extent 320x320 \
  /tmp/local-brain-selected-source.png

magick apps/desktop/assets/app-icon-processed.png \
  -resize 300x300 \
  -background '#111018' \
  -gravity center \
  -extent 320x320 \
  /tmp/local-brain-selected-processed.png

magick apps/desktop/src-tauri/icons/icon.png \
  -resize 300x300 \
  -background '#111018' \
  -gravity center \
  -extent 320x320 \
  /tmp/local-brain-selected-icon512.png

magick \
  /tmp/local-brain-selected-source.png \
  /tmp/local-brain-selected-processed.png \
  /tmp/local-brain-selected-icon512.png \
  +append \
  apps/desktop/assets/icon-concepts/local-brain-selected-icon-preview.png
```

The preview shows:

1. raw source art
2. Apple-rendered/padded macOS master
3. Tauri 512px PNG output

### 8. Optional Full Build

For production changes, run:

```bash
pnpm --filter @local-brain/desktop tauri build
```

This is heavier than icon generation because it builds the frontend, sidecar, Rust
app, `.app`, and DMG. Use it before opening a release-bound PR.

Known behavior:

- The first DMG packaging attempt can occasionally fail transiently after the `.app`
  has already been produced. Rerunning after removing stale intermediate writable DMG
  files has succeeded in prior runs.
- Do not run `pnpm tauri dev` or manual click-through smoke tests by default unless
  explicitly requested.

## What To Commit

For a selected production icon, commit:

```text
apps/desktop/assets/app-icon-source.png
apps/desktop/assets/app-icon-processed.png
apps/desktop/src-tauri/icons/**
```

Optionally commit:

```text
apps/desktop/assets/icon-concepts/<selected-or-reviewed-concepts>.png
apps/desktop/assets/icon-concepts/<contact-sheet>.png
```

Whether to commit concepts is a product/design choice. They are useful for later
comparison but not required for the app to build.

Do not commit:

- `/tmp` scratch files
- generated `.icon` packages
- generated `.iconset` folders
- unpacked `.icns` verification folders
- build products under `target/`
- screenshots unless they are intentionally part of a design record

## Troubleshooting

### The Dock Icon Looks Too Big

Cause: macOS icon artwork is being rendered too close to the canvas edge.

Fix:

- Make sure `pnpm --filter @local-brain/desktop icons` was run on macOS with Xcode
  Icon Composer available.
- Confirm `apps/desktop/src-tauri/icons/icon.icns` was regenerated after the source
  change.
- Unpack the `.icns` and inspect `icon_512x512@2x.png`; it should have transparent
  margin around the rendered icon.
- Do not solve this by adding transparent padding to `app-icon-source.png`; that harms
  other platforms.

### The Source Art Has A Border Or Rounded Tile

Cause: the image-generation prompt asked for a finished app icon, macOS tile, or
rounded-square icon.

Fix:

- Regenerate with "full-bleed square source artwork".
- Explicitly say: no rounded-square container, no black border, no outer frame, no
  transparent padding.
- Keep the full square filled edge to edge.

### The Rendered Rim Looks Too Harsh

Cause: the edge of the source artwork has a bright arc, crescent, or gradient line
that survives Icon Composer's rounded mask and specular lighting. The
`automatic-gradient` alpha, shadow opacity, and translucency value can soften Apple's
material treatment, but they may not reduce a highlight that is already baked into
the full-bleed source image.

Fix:

- First lower the generated material values in `apps/desktop/scripts/generate-icons.mjs`
  if the harshness is coming from Icon Composer's fill, shadow, or translucency.
- If the rim still looks harsh, soften the edge highlight in
  `apps/desktop/assets/app-icon-source.png` while leaving the central mark unchanged.
- Keep the background full-bleed; do not add transparent padding to the source.
- Regenerate with `pnpm --filter @local-brain/desktop icons` and inspect
  `apps/desktop/assets/app-icon-processed.png`.

### Tauri Panics With An Invalid Icon Error

Cause: malformed image metadata or unsupported bit depth. A prior failure involved
16-bit RGBA PNGs that Tauri treated incorrectly.

Fix:

- Regenerate through `pnpm --filter @local-brain/desktop icons`.
- Check `file apps/desktop/src-tauri/icons/icon.png`.
- Ensure generated PNGs are 8-bit RGBA.
- Ensure `icon.icns` is a real Mac OS X icon file, not a PNG with an `.icns`
  extension.

### `icon.icns` Is Not A Real ICNS File

Check:

```bash
file apps/desktop/src-tauri/icons/icon.icns
```

Good:

```text
Mac OS X icon, ... "ic12" type
```

Bad:

```text
PNG image data ...
```

Fix:

```bash
pnpm --filter @local-brain/desktop icons
```

### `ictool` Is Missing

The script expects:

```text
/Applications/Xcode.app/Contents/Applications/Icon Composer.app/Contents/Executables/ictool
```

Fix:

- Install or update Xcode with Icon Composer.
- Run the script on macOS.
- If running on Linux or CI without Xcode, the script will still run Tauri's icon
  generation phase, but it will not produce the Apple-rendered/padded macOS `.icns`.

### The Dev Server Rebuilds Mid-Icon-Write

If `pnpm tauri dev` is running while icons are regenerated, the file watcher can see
an icon while it is half-written and briefly report an "unexpected end of file" or
similar error.

Fix:

- Wait for the icon generation command to finish.
- Let the watcher rebuild again.
- If it stays confused, restart the dev process.

### The Generated Icon Looks Muddy At Small Sizes

Likely causes:

- too many graph nodes
- thin low-contrast edges
- central mark too small
- source art too dark
- source art relies on tiny detail instead of silhouette

Fix the prompt:

- reduce to 6-10 nodes total
- use one strong bridge
- thicken the primary graph edges
- preserve cyan/magenta highlights
- keep the bilateral silhouette clear

### The Generated Icon Looks Too Similar To Another App

For this project, similarity to Reflect's graph-node family is acceptable when the
user asks for that direction. Still, avoid direct copies:

- Do not copy Reflect's exact white connected-node sphere.
- Keep Local Brain in a darker, more bilateral, local-memory direction.
- Favor twin clusters, memory bridges, and purple glass lobes over a single
  white-node globe.

## Design Review Checklist

Before promoting a candidate:

- Does it read at 32px?
- Does it read when squinting?
- Does it avoid text and accidental letterforms?
- Does it avoid a baked rounded tile?
- Is the main mark centered?
- Is the main mark small enough and centered enough to survive Icon Composer's
  rendering, rounded shape, and `.icns` resizing?
- Do all important nodes, lobes, rings, bridge strokes, and glows stay inside the
  central 65-70% safe zone?
- For bilateral marks, are the two halves close enough together to read as one
  centered symbol instead of crowding the left and right edges?
- Does the main mark leave enough calm full-bleed background area for Apple padding?
- Does it look like Local Brain rather than generic AI?
- Does it still feel good next to Reflect and other Dock icons?
- Is the color palette close to the existing purple Local Brain scheme?
- Does it have one memorable idea rather than several competing ideas?

Before opening a PR:

- Did you run `pnpm --filter @local-brain/desktop icons`?
- Did you inspect `file` output for source, PNG, ICO, and ICNS files?
- Did you unpack `icon.icns` with `iconutil -c iconset`?
- Did you preview `app-icon-processed.png`?
- Did you include all modified generated icon files?
- Did you avoid committing scratch files?
- For release-bound icon changes, did you run `pnpm --filter @local-brain/desktop tauri build`?

  transparent margin that Xcode normally applies.
- [Successful Software: Updating application icons for macOS 26 Tahoe and Liquid Glass](https://successfulsoftware.net/2025/09/26/updating-application-icons-for-macos-26-tahoe-and-liquid-glass/)
  gives useful context on `.icon`, `actool`, `Assets.car`, and the newer macOS icon
  packaging direction.

## Future Improvements

The current approach is pragmatic and works with Tauri's existing icon configuration.
Future improvements could include:

- Checking in a real hand-authored `.icon` package if Local Brain eventually needs
  multiple layers, dark mode, clear mode, or tinted variants.
- Using `actool` and `Assets.car` if Tauri's macOS packaging path begins supporting
  or requiring newer macOS 26 icon assets directly.
- Adding a CI check that verifies `icon.icns` is a real ICNS file and that the
  generated PNGs are 8-bit.
- Adding a small script command to generate contact sheets for concept review.
- Adding a design-history folder that stores only the selected concept and final
  preview, instead of every generated candidate.
